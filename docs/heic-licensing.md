# HEIC decoder: licensing and replacement

Recorded before installing the dependency on 2026-09-27; packaging details updated the same day.

Just Upload uses **libheif-js 1.23.2**, exclusively for local HEIC/HEIF decoding. This is the necessary, isolated LGPL exception allowed in the product brief. Chromium does not provide dependable native HEIC decoding. The library is **not MIT**; its package declares **LGPL-3.0**. The MIT license of another JavaScript wrapper would not remove the LGPL obligations of the compiled decoder.

## Components and primary sources

- [libheif-js 1.23.2](https://github.com/catdad-experiments/libheif-js): LGPL-3.0. The npm package is pinned; its ESM bundle contains the decoder WASM and JS glue.
- [libheif-emscripten v1.23.2](https://github.com/catdad-experiments/libheif-emscripten/tree/v1.23.2), commit `dd5a19b878149437a5a427f6e1afa8bac624a714`: build recipe, with libheif submodule commit `ac1cb05c39008f01525c991ff8b88f84ddf70fd2`.
- [libheif source at the exact commit](https://github.com/strukturag/libheif/tree/ac1cb05c39008f01525c991ff8b88f84ddf70fd2): LGPL-3.0. Its sample applications/wrappers may use MIT; that does not change the decoder license.
- [libheif build-emscripten.sh](https://github.com/strukturag/libheif/blob/ac1cb05c39008f01525c991ff8b88f84ddf70fd2/build-emscripten.sh) enables libde265 1.0.15, and disables AOM, OpenJPEG, WebCodecs and uncompressed codecs by default. This is a decoder, with no bundled x265 encoder.
- [libde265 v1.0.15](https://github.com/strukturag/libde265/tree/v1.0.15): LGPL-3.0. Its command-line decoders are disabled in this build.
- [versioned build workflow](https://github.com/catdad-experiments/libheif-emscripten/blob/v1.23.2/.github/workflows/emscripten.yml): Emscripten 3.1.61, `USE_WASM=1 USE_UNSAFE_EVAL=0`. The artifact does not require JavaScript `eval` or `new Function`. WebAssembly compilation requires the narrowly scoped extension CSP `wasm-unsafe-eval`.

No GPL-only or AGPL component is intentionally used. LGPL-3 incorporates GPL-3 text with additional permissions, so a GPL license text in the notice file does not make this a GPL-only dependency.

## Packaging and replaceability

The build copies `node_modules/libheif-js/libheif-wasm/libheif-bundle.mjs` unchanged to
`vendor/libheif.mjs` in the extension (see the `build:publicAssets` hook in
`wxt.config.ts`). The image worker loads that separate file at runtime through the small
adapter in `src/images/heic.ts`. No decoder code is bundled into application code,
downloaded at runtime, or sent to a remote service.

**To replace the decoder** with a compatible rebuilt version:

- Build libheif/libde265 with the libheif-emscripten recipe above (or any compatible
  build exposing the same JavaScript API). Then either replace `vendor/libheif.mjs` in an
  unpacked build and load it from `chrome://extensions` → _Load unpacked_, or point the
  hook in `wxt.config.ts` at your file and run `pnpm build`.
- The adapter needs a default export returning the module, with `HeifDecoder`
  (`decode(Uint8Array)` returning images with `get_width`, `get_height`, `is_primary`,
  `has_alpha_channel`, `display(ImageData, callback)` and `free`) and
  `heif_context_free`.

Application source code and build instructions are in this repository. Reverse
engineering for debugging modifications to the LGPL library is not prohibited.

**For each distributed release:** ship `licenses/THIRD_PARTY_NOTICES.txt` (generated by
`pnpm notices` on every build, containing the LGPL-3.0 text and the libheif and libde265
notices), provide the corresponding library sources at the exact versions above (they
are archived in `docs/decoder-source/`; attach them to the GitHub release), and keep
these replacement instructions available. The separate module is an engineering
boundary, not a legal conclusion; have release packaging reviewed before a store launch.

## Limits

HEIC/HEIF still images only. Sequence brands and multi-image collections require explicit first-frame consent. Metadata is not copied to generated output; orientation is applied by the decoder, and output is rasterized. Browser-native support is not claimed for HEIC. The external image worker is terminated after a bounded execution timeout and all conversions remain on device.
